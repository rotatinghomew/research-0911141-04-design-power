# 短时复核路径

环境准备和镜像构建在操作前完成。服务的健康入口是 `/health`；服务启动即继续，不固定等待。正常本地启动在数秒内完成。若90秒内没有就绪，应停止操作并保留错误，不把等待算作成功运行。

从首页选择一个排期方案，查看现有方案的资源占用的图表与明细，点击一条记录，使用“查看原始记录”核对字段。输入会议名称并保存，然后改变所选范围；点击左侧刚保存的记录核对先前材料仍能打开，最后导出当前记录。整段交互通常需要45至75秒，不依赖远程请求。

## 设计评估路径

1. 在“查看方式”选“设计评估”，挑一个排期方案，点“评估当前方案”。页面同时显示资源账、
   识别结构、高端与低端的检出能力，以及复算配方。
2. 读“三层结论”：资源、识别、统计能力各自通过或未通过，不合并成一个判断。资源超限
   与统计能力不足同时出现时，先看是哪一层卡住。
3. 在左侧调整班级数、每班人数、轮次或时段数，必要时填 A/B 班数，再评估。每次评估都会
   变化复算指纹；比较的是不同设计，而不是同一设计反复试到满意。
4. 点“复算并比较全部方案”，表中每行保留自己的三层结论和费用，没有排名或推荐。
   点击一行可看该方案在排期表中的资源核对。
5. 比较表下方可“保存这次比较”，把方案清单、假设与仿真设置一起冻结；单方案记录也
   可保存。保存后 `GET /api/notebooks/编号/verify` 会按冻结输入重新复算并核对指纹。

`fixtures/data.json` 可用于重新导入核对。页面说明的是观测和适用范围；不要为了演示修改数据以制造某种优胜、显著性或异常结论。新增加的分析也应从真实可用证据解释结果，不要求出现某个指定方向。
