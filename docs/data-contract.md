# 数据口径

plans 指出班级数、每班招募数、测量轮次和整班因素安排。slots 的 seats 为单时段容量，rooms 为并行机房数，成本单位为元。factors 指明班级或学生随机化层级，estimands 是业务关心的对比而非指定估计器。historical 中 variance_ranges、absence_ranges 是规划区间，不是真值；相关参数可调整。设计的随机种子和仿真精度应随方案保存。

## 数据版本

`fixtures/data.json` 是可直接导入的一份完整材料，`product.json` 保存页面默认范围。导入必须提交完整对象，不把省略字段解释为删除补丁；以规范化 JSON 的 SHA-256 标识内容，同内容多次导入复用版本。原始记录只追加版本，保存的分析材料始终指向原来版本。

页面中的范围影响当前描述，不回写源数据。`null`、缺记录与实际零不能合并；数据格式问题应在导入时明确报错，而不是生成看似成功的空结果。涉及单位、时间或关系的解释以本文件为准，统计方法和业务决策没有预设结果。

## 目录

`design_power/domain.py` 提供现行领域校验和描述，`validation.py` 处理基础引用与数值校验，`service.py` 连接领域操作和材料存档，`storage.py` 负责内容寻址数据与历史记录，`server.py` 提供本地接口。`web/app.js` 使用接口构建交互页面，不自行推导独立口径。
